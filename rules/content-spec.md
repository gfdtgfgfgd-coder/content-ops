# 内容生产规范

> 最近更新时间：2026-11-11
> 业务规范唯一源。风险词与正则不在本文复制，统一读取 `rules/banned-words-quick.yaml`；封面基础色值见 `rules/cover-palettes.json`。本文件供生成脚本、Hanabi 操作规范面板和规划复核共同使用。活动块有当前证据才写；没有证据时写使用前注意。

## 账号调性与通用红线

冲突时按这个顺序取舍：可核验事实和来源边界，高于已确认的身份与销售授权，高于平台和账号现行限制，高于传播结构，高于促销语气。

先确认任务事实、目标平台和账号身份，再开始写稿。小红书表达要普一点、不油腻、不偷袭：像普通用户分享，避免品牌口号、堆叠感叹号、熟人式称呼；不借事故或热点踩竞品。没有来源的评测结论、性能数字、价格、库存、活动和用户体验一律不编造。

严禁出现「终身免费」「永久免费」等未经官方长期承诺且随时变动的虚假宣传。

历史帖子、模型语料里的旧句，以及风险词的替换建议，只作表达或结构参考。它们不是当前产品事实，也不是平台过审保证。技术容量不能写成购买额度，例如百万上下文不是百万额度。

所有对外可见内容，包括标题、正文、封面、图片 OCR、标签、群公告和按钮文字，均不得出现境外模型品牌或型号。

小红书与闲鱼的对外内容还不得出现 API 字样。

旧样本或用户提供的原文不能豁免。具体违禁词、正则、适用平台和替换建议只维护在 `rules/banned-words-quick.yaml`，生成前后均用该源检查。

运营偏好证据的可编辑来源是 `skills/simin-persona/SKILL.md` 与 `data/wecom/simin-feedback.jsonl`。反馈原文及截图只留本机 `data/wecom/raw/`；入库引文必须去敏并能用证据编号追溯。偏好规则只增不删，出现冲突时保留证据并交规划 agent 复核，不静默覆盖。偏好里的价格反差、占便宜钩子和固定接驳句，只有本轮简报或已核实事实写明当前活动、报价或工具条件时才能使用。没有这些证据时，不用偏好句式补造促销或兼容。

## 公开核查与写稿顺序

写 GLM-5.3 和其他型号都走下面的顺序。其他型号的语料正文没有在本轮改写；某个型号还没有事实账本时，不把语料句当成能力证明。

| 步骤 | 输入 | 操作 | 过不了就停 |
|---|---|---|---|
| 0 建档 | 完整型号、平台、账号身份、任务目标 | 分清科普、体验或销售；分清主模型和高速变体 | 未知不补造。销售资质未确认时，不写售卖和官方身份 |
| 1 公开核查 | 官方发布、当时文档、模型卡 | 实际打开页面，记下页面日期、抓取日、摘录、型号、条件和链接；核对互相矛盾和过期活动 | 每个数字和当前可用性都要有来源。没打开的网页不算核验。官方自测必须标明，不能写成独立验证 |
| 2 写成价值 | 来源账本、目标人群 | 按能力、用户任务、可能价值、边界来写，并标出事实、推断或建议 | 主卖点最多四项。分数升幅不写成省下的时间或成本。缺证据就删，不换近义词 |
| 3 选真实形式 | 目标平台、人工精选、版式 | 小红书优先 `label.good`，闲鱼先按想要人数排序再核对原帖。一篇只选一种版式 | 记下参考编号、节奏和字数。图不可读就停止视觉验收，不用封面 OCR 假装看过图 |
| 4 写正文 | 卖点矩阵、结构 | 按下一节结构写。活动有当前证据才写，否则写使用前先看 | 标题不超过 20 字，型号写全。不虚构亲测。内部链接不贴进短帖 |
| 5 审核 | 草稿、风险词库、事实账本 | 逐项核对版本、数字、日期、输入类型、部署条件、商家承诺和全部可见文字 | 不留下未证实的完整记住、必成、无限、无人看管或零错误。安全内容只写授权范围内的自查，不写利用步骤。词检不能代替事实审核 |
| 6 封面 | 独立封面短字、可读参考图 | 按视觉规范留白并核对字形。小红书 1080×1440，闲鱼 1080×1080 | 未出图或未看图时只交文字方案，不能标视觉验收通过 |
| 7 人工放行 | 完整稿、证据、当前活动材料 | 负责人确认事实、身份、活动和版式。发布前重查会变的页面 | 另有明确发布指令才可发布。有稿件不等于可发布，也不自动入库 |

## 标题与正文结构

标题控制在 20 字以内（含标点和 emoji），优先学习本地近期真实标题的句式、语序、标点和长短节奏；近期样本不足时再参考所选素材。不得整批套用「短促感叹！型号＋卖点」或只换感叹词。历史句式不是固定模板，不强制感叹或号召起手。标题须完整成句，超长应重写而非硬截断；型号太长可不放在标题，放正文明确说明；出现型号时须原样保留输入名称。没有当前低价证据时，标题不喊低价，也不催单。标题、正文仍须避开历史原句及未经证实的事实，同批更换切口。开头引入以手机端两行、约 25–34 字为目标，先写痛点、发现或提问。

核心卖点上方可加一行模型引导头。卖点输出该模型的 4 个核心大卖点，冒号前面必须是普通人能一眼看懂的清晰大卖点，严禁使用生僻黑话，严禁出现「毫秒级」「秒级」等速度夸大词。冒号后面用 1～2 个极短句做解释，每个短句控制在 6–12 字。例子只说明句式，不能把「低延迟」或「直接给出可用补丁」写成事实。同批次每篇更换切口。

能力区的当前执行口径是：每条卖点只用一个冒号，把卖点名和短解释分开。开头、活动或使用前注意、结尾不再排成连续冒号。旧语料禁止连续冒号，旧规范又要求卖点使用冒号，这里取保守的一边：能力区保留单冒号，其他区块不用冒号履历。负责人可以再改这条约定；改之前生成按此执行，并仍要求卖点含加粗。

1. 开头、核心卖点（4点短句）、活动或使用前注意、行动钩子。
2. 开头、核心卖点（4点短句）、活动或使用前注意、国内合规工具或接入方式（已核实时写 CC、wbuddy 等接驳话术，未知则写先核对）、使用场景（每篇换新）、行动钩子。
3. 开头、核心卖点（4点短句）、活动或使用前注意、接入方式、适用人群（每篇换新）、行动钩子。

第三块的机器字段名仍是 `price`，长度为 1–3 行。只有本轮简报或已核实事实写明当前活动、报价或服务范围，才写活动或价格反差，并且不能超出证据。没有这些证据时改为「使用前先看」，说明输入类型、结果需要验收、工具需要先核对。不伪造亲测、低价、库存、授权或紧迫感。下面的形式只在已有证据时使用，不是每篇必填促销。

有证据时，价格与活动板块严禁写成没有重点的一堆平淡文字，也**严禁机械反复套用同一种单一符号模板（如只知写「‼️限时活动‼️ 💰 💰」）**，坚决删除「限时特惠」「超低调用开销」等促销夸大用语，必须根据主题采用富有性价比说服力、生动多元的高亮形式：
- 形式 1（算账对比式）：`💡 成本算笔账：\n连续重度跑上一整天，算下来还没一杯咖啡贵，放开手脚随便用。`
- 形式 2（降本窗口式）：`🔥 趁着这波降本窗口：\n使用门槛大幅降低，日常排错、跑长任务再也不用精打细算。`
- 形式 3（算力自由式）：`💸 算力更友好：\n性能大幅跃升，日常使用压力更小，复杂大项目全天放开跑。`
- 形式 4（活动高亮式）：`‼️好消息‼️好消息‼️\n白菜价来了，高频调试完全不心疼` 或 `活动重磅来袭：\n💥【模型名】便宜稳定，日常使用毫无压力`
小红书不写具体金额或折扣数字。闲鱼只有在用户明确给出金额时才写具体价格。公众号价格引用须有可核验来源与日期。

工具接驳行**严禁使用 `Roo Code`、`Continue`、`Cursor` 等海外或第三方插件名**，统一替换为 **`CC`、`wbuddy`、`Trae`** 及本地终端、自动化脚本等接地气、开发者日常口吻的多样化表达。结尾段落（工具接驳、场景/人群、行动钩子）**坚决严禁机械死板地套用同一套格式（如反复出现「🔌 原生支持接入...」「📌 适用场景：...」「...这波好价别犹豫，火速安排上！🚀」）**，必须根据不同封面主题采用截然不同的结尾编排：
- 形式 1（自然工作流接驳流）：`🛠️ 接进日常环境：直接拉进 CC、wbuddy 或者终端自动化脚本...` + `🎯 适合人群：...` + 干净钩子；
- 形式 2（直观痛点场景清单流）：省略冗余工具行，直接采用打点清单列出核心可做场景（`📌 适合拿来干这几件事：• ... • ... • ...`）+ 干脆行动指引；
- 形式 3（极客上手体验与推荐流）：`💻 上手体验：支持直连本地终端与自动化流水线，配合 Trae 或 CC 即调即用` + `👥 推荐给：...` + 爽感钩子。
结尾行动钩子优先带上完整型号和低风险下一步。有当前证据时才写好价窗口。同批次更换句式。不写未经证实的必成、无限量或无人看管。

## 封面大字报与视觉规范

### 封面与正文解耦

正文负责展开「引入 + 4大卖点 + 活动或使用前注意 + 接驳/场景/人群 + 钩子」。**正文内容（body）严禁传给生图环节，严禁把正文长句照搬上封面**；文案模型的 title_lines、cover_subtitle、cover_highlight 仅兼容历史稿和显式离线排版，不能作为在线生图文字来源。

封面文字只负责抢眼球、激发好奇与询价购买欲，结合 `data/model-corpus.md` 当前模型的封面专节创作独立短字，短词库只供表达参考：字少、直白、爽点突出，保留完整模型名。询价购买欲是传播目标，不要求印出「询价」字样。所有候选必须服从风险词唯一源；示例若与现行禁词冲突，采用规则允许的替代词，不放宽拦截。语料只是表达素材，不作为能力或活动事实证明；不编数字、承诺、价格或体验。所有封面短字与最终视觉提示词均经 `words.check` 校验；封面跨平台统一同时遵守现行小红书与目标平台两套风险词红线，禁具体折扣，不写境外模型名。

### 四大合集版式结构（归属唯一源：data/collections.json）

1. **大字报（小红书主力）**：纯文字/备忘录/纸张便签版式，3～4 行中粗无衬线字，局部荧光笔或色块高亮，角落仅放极简引号、箭头、小表情等符号或小贴纸。文字整体居中，左右各留至少画布宽度20%的安全区，文字总跨度不超过60%；行间空隙至少约半个字高。**严禁出现任何 3D 物件、代码屏、电脑插画、人物插画或复杂背景**。四行文字顺序为「占便宜/发现钩子（妈呀，被我挖到了/真白菜价/就离谱！） + 核心利益（便宜量大的/便宜又管饱） + 完整模型名 + 4～6 字直白爽点（写代码太丝滑了/跑任务嘎嘎快）」。按参考图允许合并为三行，爽点以短促可读为先；完整模型名不受普通短句字数限制。以上居中、20%边距和默认中粗无衬线字体是自动生成默认；用户在成稿编辑器主动调整时，可选择左对齐、60%～150%总字号与每行字号（相乘生效），`config/cover-fonts.json` 中的可用字体（黑体/宋体等），以及背景亮度/对比度/饱和度/色温（只改底图、不改封面字），文字区随字号与字体变化，保持整组垂直居中、不裁切文字及高亮，左右至少保留5%画布安全边距。
2. **上中下**：标题/主场景或演示/下方总结形成纵向阅读，比例按信息需要安排；主体可重新选择，能力模块可分布在主场景附近，不要求照搬原图吉祥物或固定胶囊数量。
3. **左右下**：通过左右主次、图文/功能与演示关系组织信息，下部可承接总结；不是必须左字右图，更不锁死左右宽度和底栏位置。
4. **环绕**：中心主视觉与周围能力模块形成关系，模块按主次、分组和阅读顺序组织，不强制对称四卡。信息海报允许一条2～12字数单位的利益短句与3～6个简短能力标题，有足够空间和事实依据时可配同数短副标；单个能力标题≤8字数单位、副标≤12单位，不为了凑数量增加能力或随机小字。

上述是抽象信息结构，四类均可用于小红书和闲鱼，按平台调整画幅。合集归类先忽略型号、配色、机器人/电脑/纸张等偶然元素，判断信息层级、视觉重心、阅读路径和模块作用；优先使用现有合集，只有抽象后确实无法容纳才新增。画面复杂不代表表现好，精选必须另看可核对的互动数据，保留人工选择，低样本不强行标高表现。

### 手动封面编辑

用户在图片编辑器中修改的封面字以当次输入为准：型号行可改，允许型号与原批次不同、在其他行重复出现；不套用自动生成时的型号唯一性和角色短句字数要求，也不自动纠正或截断用户输入。预览、保存排版、按提示词重绘使用同一手动文字校验；保留每行1～80字单行格式、渲染参数及风险词检查。自动生成仍遵守下述创作约束。

### 先充分抽象，再独立设计

先填写 `communication_brief`：受众、一个有来源的主利益、预期反应、视觉记忆点；再填 `art_direction`：整体创意、利益/型号/主视觉关系、图形语言、辅助信息与容器必要性。缺价格依据可从已有用途或痛点切入；副标提供用途或关系，不重复同义词。完整型号可自然换行、融入构图。

主视觉可承载情绪、识别或利益隐喻，不必是功能终端。外框、展台、卡片按内容需要使用，不默认大设备加三张等宽卡；辅助信息可融入场景、字形或图形组，三列本身不是禁区。

手选优先；未选时从同平台合集按型号、人工精选和同账号互动分配不同参考。观察原图及 `visual_abstraction`，反推词不继承旧文案、型号或复刻限制。

抽象层级、重心、路径、模块和疏密，也保留字形级差、对比、动势与装饰节奏；不默认极简或灰白卡片。合集不锁坐标、比例、行数、卡片数或物件。`creative_plan` 记录保留关系、至少三项重新设计及信息预算。

保留丰富参考的有效信息容量，不用主题标签、随机图标、小字、占位块或重复流程凑数。主视觉、次级信息与装饰有主次，透视、光照、材质和配色统一。`module_plan` 写各部分新增信息；界面可用至多8个短 `scene_labels`，逐项风控，不增加能力/数据/效果主张；大字报不加界面标注，保持文字主导和有限平面装饰。

材料已有能力可转为具体场景与用途图示，缺独立facts不等于删掉这些方向；词库仅供参考，保留来源和证据边界，不冒充本方实测或当前权益。同批更换切口、主体/背景组合、编排或节奏，不只换色、动作或末行；品牌主体可保留。生图前仍拦截重复钩子、主体/背景签名及大部分非型号短字，事实和风险边界不放宽。

大字报采用图层分离：视觉模型从参考图分别提取背景材质、底色、文字色、强调色与高亮行；区分揉皱纸、深灰网格、蓝色笔记本、光影纸张和彩色便笺，不把所有参考图统一成薄荷网格加暖白卡片。图像模型只生成无字材质底图，纹理与明暗贯穿中央排字区域；本机材质层补足纸纤维、褶皱或所选网格，禁止再用不透明白卡抹掉底纹。Pillow 按 `config/cover-fonts.json` 解析本机中文字体排字（默认中等字重无衬线），锁定既定留白、文字宽度与行距；高亮颜色与位置按本次创意方案，深色背景改用浅墨色，高亮条上的字单独校验对比度。其他三类仍由图像模型直接生成完整海报。自定义画面描述在合集的抽象结构内生效。按平台规格重排到小红书 1080×1440、闲鱼 1080×1080，保护文字和底栏安全区。

大字报背景默认是铺满画布、延伸至四边的连续材质，画面本身就是纸面或背景；不得套成“大底板里放一张小纸”的结构，不加内嵌纸框、第二张纸、四边闭合投影或固定角落加号。光影表现为自然、连续的明暗变化；网格只在选定材质需要时出现，不因“纸张/便笺”字样统一叠加。

颜色可从 `rules/cover-palettes.json` 起步，不把参考色值写死。最终须核对实际渲染文字、错字、对比度、主体和留白；未经真实生图及目视检查的效果明确标注未验。显式 --background 仍保留既有 Pillow 离线排版，不能冒充多模态同构生图。

## 小红书、闲鱼与公众号

### 小红书

语气自然克制、客观真实，避免油腻称呼、极端夸大、硬广口号和偷袭式比较。**坚决严禁出现「限时特惠」「超低调用开销」「批量调用」「地板价」「降到底」「最爽」「彻底解放」「零负担」「全自动搞定」「秒级/毫秒级」等促销用语、敏感行为词及绝对化极限承诺**。活动窗口不是每篇必填；没有当前活动证据时，把该段写成使用前注意。亮点解释使用具体功能，不写「代码直接自己写」「全自动搞定」「一次性吃透」等未证实承诺。标题不超过 20 字，正文按移动端短句与段落留白排版。价格只写用户给定且符合本平台规则的非金额表达；具体词库以风险词唯一源为准。平台尺寸为 1080×1440。优先用运营人工红勾选出的优质帖作风格参考，不把高互动等同于内容事实。

### 闲鱼

按个人卖家口吻直给。标题可以写型号和用途；不使用「官方」「旗舰」等容易造成身份误解的称呼。没有当前商家资料、报价、售后和授权时，只写信息草稿，不装成可以成交的商品。金额仅能来自用户提供的当前价格。素材质量排序看「想要」人数，使用 `data/posts.jsonl` 中 `metrics.wants`，并列时保持稳定排序。方图为 1080×1080；平台迁移须重排信息并保护底栏与安全边距。

### 公众号

采用长文和完整论证，区分事实、推断与建议；关键数据、价格和时效性结论须给出来源或核验记录。排版实现参考 `gzh-design-skill`，去 AI 痕迹可调用仓库已安装的润色技能，但润色不得改变事实。公众号同样遵守全平台对外内容红线。

## 参考素材选用

抓取边界遵循已确认范围：优先使用人工书签「素材参考」、目标账号置顶帖，以及经确认的关键词补充；不做全站全扒。账号与置顶链接的机器可读源为 `data/sources/bookmarks-raw.json`，浏览器抓取须遵守 `AGENTS.md` 的限速、断点续抓和验证码即停规则。

小红书参考优先采用思敏企微勾选并已在 `data/posts.jsonl` 标为 `label.good = true` 的内容；闲鱼参考依 `metrics.wants` 排序并核对原帖。选择参考前检查平台、发布时间、事实相关性、风险词和可见图片；旧内容只借鉴节奏、结构和视觉组织。不同平台、不同模型或不同任务角度不可机械套用同一篇。旧帖里的价格、稳定性、活动时间和多型号捆绑不继承到新稿。

## 模型语料库

`data/model-corpus.md` 是 GLM、Kimi、DeepSeek 等模型的创作语料和案例索引，供构思与表达去重。它不是事实源、规则源或模型能力证明；与本规范、风险词库、已核实资料冲突时，以规则和事实源为准。GLM-5.3 的生成默认只采用该文件「生成可采用的边界」；同节后面的供稿长文、标题库和价格句供人工核对，不自动当事实。


### 近期避重与账号热度参考（2026-11-09）

每次生成前读取素材库中最近7天至今的真实发布日期，检查标题、开头、主要卖点组合、场景和封面短字；不得照搬，也不得仅换型号、emoji或同义词。参考图可借结构、节奏与配色，内容须另选切口。同批成稿也互相避重；标题/正文达到机器相似阈值会拒绝并在已有有限重写次数内重新生成，仍雷同则明确失败。语义层面的相似仍需人工复核。未知发布日期不冒充旧帖；抓取时间不是发布时间。

自动参考保留平台、合集、版式、人工精选与型号相关性约束；在同等候选中倾向同账号互动较好的帖子。只根据真实可见的点赞、收藏、评论及带时间的快照计算相对权重，未知指标不记为0；不足样本和互动量不加权。发帖时长与后续增长用于修正比较，不称已证明爆款、曝光、转化或效果因果。不复制热帖的原文、数字、旧活动或能力承诺，不因热度放宽风险词。策略参数唯一在 config/data-cleaning.json 的 monitoring 节；原始日期与互动快照只维护在 data/posts.jsonl。

目标账号与采集入口沿用 data/sources/bookmarks-raw.json。每日北京时间0点读取新近图文并刷新已入库帖的互动；遇登录失效、验证码或访问限制即停并报告缺口。近7天新帖按ID去重入库；旧帖保留用户维护的正文、图片、精选和合集，仅补日期及互动。未分类新帖不擅自加入四大人工合集。
