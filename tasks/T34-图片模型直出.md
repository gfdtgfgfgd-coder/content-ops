## 目标

把出图改成**文本模型写提示词、图片模型直接出整张图**：

```
前端接口（需求）→ 文本模型（读需求 + 语料 + 事实）→ 写文案 + 写图片提示词 → 图片模型直出图片（含中文文字）
```

本机不再排版、不再叠字。现在的 `cover()` 用 Pillow 画三行字 + 色块，做不出功能牌、底栏、价格牌，所以图永远达不到要求——这条路废除。

成本：0.25 元/张，两个平台都是 1 张/篇，6 篇/天约 1.5 元。

## 输入

- `scripts/gen-xhs-post.py`：`cover()` 本机排版与 `--background` 缓存排版路径（待替换）。
- `scripts/gen-image.py`：`POST /v1/images/generations`，参数 `model / prompt / size / n=1 / watermark=false`。
- `outputs/2026-11-03/` 三份提示词文档：作为「提示词该怎么写」的范例（文字清单、层级、留白、禁用元素），不再当成品配方。
- `rules/design-rules.md`、`rules/platform-rules.md`、`skills/xhs-post-generation/SKILL.md`。

## 设计要点

- **文案与提示词一起返回**：文本模型输出 `{title_lines, body, tags, angle, image_prompt}`。`image_prompt` 是给图片模型的完整描述。
- **尺寸走参数，不靠提示词**：小红书 `size=1080x1440`（精确 3:4），闲鱼 `size=1080x1080`（1:1）。提示词里重复写尺寸不算数，以请求参数为准。
- **提示词必须自带准确文字清单**：型号逐字、价格短句、服务语（好价/量大/快速稳定）；写清层级（型号最大、价格第二层）、留白比例、禁用元素（水印、logo、乱码、错字、多余英文）。
- **图文字错就是失败**：中文渲染不可靠是已知风险，所以先花 0.25 验一张；不准就停卡改方案，不硬建批量。
- **不自动重试**：生图失败或文字明显错误，记录失败并标注，不自动重复收费请求。
- **保留临时回退**：`--image-mode model`（默认，直出）与 `--image-mode local`（旧 Pillow 排版，仅供回退），下一张卡再删本地路径。

## 步骤

1. **先验证一张（已获授权，0.25 元）**：取 `outputs/2026-11-03/kimi31-cover-prompts.md` 里一条提示词，改写成“文字清单 + 层级 + 禁用”写法，用 `1080x1440` 出一张，检查：中文是否清晰、型号是否逐字正确、价格短句是否可读、有无乱码水印。记录耗时、费用、成图路径。
2. **判定**：文字基本准确 → 继续；糊字或错字 → **停卡**，写出失败模式，不继续建链路。
3. 改脚本：文本模型输出增加 `image_prompt`；新增 `--image-mode`，默认 `model`；默认路径不再调用 `cover()`。
4. 生图调用：按平台传 `size`，每篇 1 次，`n=1`、`watermark=false`；把模型、尺寸、费用写进 manifest。
5. 提示词质量：给文本模型一段固定的「提示词写法」（提炼自三份 outputs 文档：必写文字清单、层级、留白、禁用元素），并要求逐条自检。
6. 失败处理：非零退出或校验失败就记 `image_status=failed`，不重试；续跑只补缺图。
7. mock 网关：断言 `image_prompt` 非空且含型号原字符串、`size` 正确、每篇 1 次调用、无重试；再构造一次 500 验证失败可被记录。
8. 更新 `docs/GUIDE.md`（生成流程改为直出、费用说明、失败怎么办）、`README.md` 现状表、进度表；归档；中文 commit 推送。

## 规矩

- 不自动重试收费请求；失败就记，不硬来。
- 尺寸只走参数，提示词里不靠文字描述凑比例。
- 提示词里的文字必须来自 facts 与用户提供信息；不编参数、价格、活动。
- 不改 Hanabi、不动 rules、不发布。
