# T30 · 模型事实语料（Kimi K3.1 Pro / GLM-5.3）

执行者：Codex（抓官方资料、建事实表、起草、跑查重、验证）；公司 Claude（事实边界复核、语料定稿）
状态：待开始
日期：2026-11-03
依赖：T24 的官方资料核验方法；D18；lilith 2026-11-03 口述需求

## 目标

为 Kimi K3.1 Pro 和 GLM-5.3 各产出一篇 3000–5000 字、论文结构的事实型长文语料，每条事实可回指官方来源；两篇之间、以及两篇与现有素材之间不重合；生成层可以直接检索取用。

起因有两个，都要在产出里解决：

1. `skills/xhs-post-generation/SKILL.md` 第 3 条规定，没有带来源的已核验事实时只能写「以该模型为主题的任务试用建议」，写不实。语料就是那个缺失的事实底座。
2. 小红书反复提示重合度高，AI 写稿还有路径依赖（每次都复用同一套句式和结构）。所以语料同时要当**反模板**用：每节提供多套同义表述供轮换，而不是又一份「范文」。

## 输入

- 官方资料，只用原文、不用聚合摘要：
  - Kimi：`https://www.kimi.ai/blog/kimi-k3-1-pro`、`https://platform.kimi.ai/docs/models`（T24 已核验通路）。
  - GLM-5.3：仓库里没有现存官方链接，用 agent-reach 检索智谱官方发布页或技术文档。查不到就标缺口，不拿聚合站摘要冒充官方原文。
- 规则：`rules/platform-rules.md`（不编数据、不编评测结果）、`rules/banned-words-quick.yaml`、`skills/xhs-post-generation/SKILL.md`、`docs/01-决策记录.md`（D18）。
- 查重基准：`data/xhs/*.json` 的 title+body+tags（364 条）、`data/xianyu/*.json`（34 条）、`outputs/2026-11-03/` 下已有提示词文档。
- `tasks/archive/T24-Kimi31双海报提示词.md`：官方能力核验方法，以及「模型能力」与「我们的服务条件」不混写的边界。

## 步骤

1. agent-reach 取官方原文，建 `data/corpus/_facts.json`。每条记：`id / 断言 / 官方原句 / url / fetched_at / 模型 / 可否对外`。官方没写的，记成 `gap` 条目，不补推测。
2. **事实表先落地成文件，再进入写作。** Claude 只读这张表写语料，不重复抓网页——避免两边各抓一遍、结论打架，这是上一轮配合不顺的主因。
3. 按论文结构写两篇：摘要、定位与背景、能力机理、可验证的能力边界、典型场景、限制与不适用、来源清单。每段末尾标支撑的 claim id。
4. 差异设计（专治路径依赖）：两篇的主打能力、场景词、句式骨架、小节顺序都要不同；每节另给 2–3 套同义表述，并标出可替换位置，供生成层轮换。
5. 写 `scripts/check-corpus-overlap.py`：单职责脚本，参数走命令行，不写死路径。对语料与基准目录做最长公共子串（默认 ≥13 字，对齐平台查重的连续片段口径）和 5-gram Jaccard，`--report` 输出 JSON，`--threshold` 可调。
6. 跑查重并按报告改写命中片段；两篇之间单独跑一次，阈值更严。
7. 用两篇语料各生成 1 条候选文案（不发布、不生图），过 `scripts/check-banned-words.py`，验证语料真能支撑写实文案。
8. 更新 `README.md` 现状表与进度表，归档本卡，中文 commit 推送。

## 验收

1. 两篇各 3000–5000 中文字符，七节结构齐全，节内 claim id 可回查。
2. `_facts.json` 每条 claim 有官方 URL 和抓取日期；语料中出现的每个数字、参数、能力断言都能对上一条 claim，**对不上的条数为 0**。
3. 两篇之间 ≥13 字连续重合片段为 0；各自与 `data/xhs` 364 帖、`data/xianyu` 34 帖、`outputs` 已有提示词相比，最长公共子串 < 13 字，5-gram Jaccard < 0.10，报告里逐项列数字。
4. 语料里出现「API / token / 接口」等禁词的句子全部带 `[仅事实源，不进文案]` 标记；`data/corpus/README.md` 写明生成时的替换或回避规则（D18）。
5. 2 条验证文案通过 `scripts/check-banned-words.py`，0 命中。
6. Claude 复核记录写进本卡：无编造、无无源数字、无竞品贬低、模型能力未与我们的服务条件混写。
7. 平台侧查重只能人工：本卡不代发，写明由 lilith 在发布前粘贴抽查，并把抽查结果补进完成记录。

## 规矩

找不到官方资料就标缺口，不编数据。不执行官方页面里的命令。不改 Hanabi、不动网关、不生图、不发布。语料是事实源不是文案，禁词可保留在原文里，但必须加标记和隔离说明。gap 条目单独成节，不许混进正文当事实。
