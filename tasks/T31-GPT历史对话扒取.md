# T31 · GPT 历史对话扒取与协作模式提炼

执行者：Codex（浏览器抓取、落盘、索引）；公司 Claude（提炼结论复核）
状态：待开始
日期：2026-11-03
依赖：lilith 在 ego-lite 中打开并登录 ChatGPT 网页版；D5、D6、D8

## 目标

把 lilith 自己 ChatGPT 网页版里这些天的历史对话扒成本机档案（原文只留本机、不进 git），再提炼成一份可进 git 的《协作模式》文档：需求该怎么写、哪些配合方式有效、哪些反复踩坑、有哪些结论可以直接复用。

直接用途：给后续任务卡（含 T30）提供「lilith 的真实写法与验收口径」，别再靠我猜。

## 输入

- lilith 届时打开的 ego-lite 与已登录的 ChatGPT 网页版（只读，不进登录流程）。
- `AGENTS.md` 抓取限速条款（单账号每分钟 ≤10 个动作、每 50 条休息 5 分钟、支持断点续抓、遇验证码或登录失效立刻停）。
- `docs/01-决策记录.md` D5（登录态走真人路径）、D6（限量、不全扒）、D8（原文只留本机，进 git 的只有提炼物）。
- `skills/` 下任一份 SKILL.md 的结构作为提炼文档格式参考。

## 步骤

1. 等 lilith 打开 ego-lite 并停在 ChatGPT 会话列表，截图确认登录态。**不代替用户登录**。
2. 读会话列表：虚拟列表只渲染可视区，靠滚动加载到 `hasMore=false`，每条取 id、标题、更新时间、消息数。不数 DOM 中的可见节点当总数。
3. 逐条进会话导出消息（role + 正文 + 时间），写 `data/gpt-chat/raw/<id>.md`。断点续抓：已存在于 `conversations.json` 的 id 直接跳过。
4. 限速执行并留日志：每分钟动作数、每 50 条的休息。验证码或登录失效立即停止，把现场写进本卡「完成记录」，不硬闯。
5. 索引与统计写 `data/gpt-chat/conversations.json`（只含元数据与主题标签，不含正文）。先把 `data/gpt-chat/raw/` 加进 `.gitignore`。
6. 提炼 `data/gpt-chat/协作模式.md`：① 我写需求的有效句式 ② 有效协作模式 ③ 失败模式与当时症状 ④ 可复用结论（含推荐落到哪张卡或哪个 skill）。每条结论至少引 1–2 条对话 id。
7. Claude 复核提炼结论与引文是否对得上，更新进度表与 README，归档本卡，中文 commit 推送。

## 产出

- `data/gpt-chat/raw/<id>.md`：原始对话（不进 git）
- `data/gpt-chat/conversations.json`：索引与统计（进 git）
- `data/gpt-chat/协作模式.md`：提炼结论（进 git）
- `.gitignore`：增补 `data/gpt-chat/raw/`

## 验收

1. `git status` 里不出现任何 raw 对话文件；`conversations.json` 通篇无对话正文。
2. 索引条数与网页实际会话数一致；不一致处写明缺口会话的 id 和截断原因。
3. `协作模式.md` 每条结论引 1–2 条对话 id，抽查 3 条能回查到原文。
4. 抓取日志含时间戳与动作计数，能看出限速确实执行过。
5. 演示一次断点续抓：中断后重跑，已抓 id 不重复抓。
6. Claude 复核记录写进本卡。
7. 全程只读：不修改、不删除、不在 ChatGPT 里发送任何消息。

## 规矩

只读、限速、可续。原文不入库，提炼物才入库（沿用 D8 口径）。抓不完就记缺口，不硬闯登录或验证码。本卡不涉及发布、生图和 Hanabi 改动。

## 完成记录

（Codex 填）日期、实际抓到的会话数与缺口、限速执行情况、遇到的问题。
