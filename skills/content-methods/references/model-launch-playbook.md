# 模型上新与 API 调用文章手册

本手册用于 AI 模型发布、平台接入新模型、API 上新、模型测评、卖点分析和促进模型调用的公众号文章。它是专用模块，不替代炼丹炉原有的调研、账号风格、工作流和去 AI 味规则。

## 写前输入

确认或从资料中推断：模型名与准确版本、发布日期或接入日期、平台名、访问方式、兼容接口、价格或活动、目标用户、适合与不适合的任务、可用案例、风格样本，以及一次性交付还是分段交付。

若用户明确说还会继续提供多篇样本，先收齐再提炼稳定特征，不在第一篇样本后提前成稿。用户修改过的版本是最新风格依据；保留已确认段落，只修改指定区域及维持连贯性所必需的邻近内容。

用户明确说“先学参考再写”时，先阅读其指定/提供的样本，概括样本间的切口差异与可迁移方法，并说明当前具体缺口；不要提前输出完整稿。用户确认开始调研/写作后再推进。收到竞品文章或生成式润色稿时，把它们当成观点和表达样本，关键事实仍须回到原始来源核验。完整协作示例与用户纠错记录见 [model-launch-window-retrospective.md](model-launch-window-retrospective.md)。

## 模型专用主张账本

起稿前建立内部账本：

| 主张 | 类型 | 一手来源 | 辅助来源 | 核验日期 | 置信度 | 安全表述 |
|---|---|---|---|---|---|---|

主张类型：

- **已验证事实**：当前一手来源直接支持。
- **厂商主张**：明确归因于模型厂商，不写成编辑部验证结果。
- **第三方结果**：写出评测方、基准、模型版本/模式和测量日期。
- **计算**：保留操作数与公式，精确计算后再按需要舍入。
- **推断**：写明这是解释，并限制在证据允许的范围内。
- **未验证**：删去，或在确有必要时明确标注尚未确认。

优先核验官方公告、API 文档、模型卡、论文、基准维护方和一手评测页面。新闻与社区截图只作辅助；瞬时榜单必须标日期，并尽量回到榜单所有者页面。

## 高风险推理边界

- 基准同分不等于所有任务可互换，也不等于“全面追平”。
- 单任务评测成本、API 标价、Token 效率和生产环境总成本是不同概念，不得互相代替。
- 未独立取得 Token 用量时，不能从单任务成本反推 Token 效率。
- “提升 19.8 个百分点”不能写成“提升 19.8%”；相对增幅必须显示基数和计算方式。
- 比较必须写明对象。不要只写“四分之一成本”，应说明相对哪个模型、哪项测试、哪一日期约为多少。
- 拒答可能让某些“非幻觉”指标更高；解释时同时查看准确率、作答率或基准定义。
- Office 文件、工具调用或浏览能力可能来自 Agent 框架，不一定属于裸模型能力。
- 发布时间、上下文窗口、吞吐、价格、折扣和可用区都具有时效性，发布前再次核对。
- 网络安全评测分开记录漏洞发现、验证与利用，注明白盒／黑盒、权限、工具链、样本、成功标准、基准版本和日期；不同任务基准不能拼成综合安全排名。本地部署个案须分别核对事件报告、数据流和模型作用，不外推为普遍防护能力。

表述强度示例：一手事实可写“官方 API 文档显示”；第三方结果写“某评测方当期榜单显示”；有限证据写“现有测试至少说明”。除非证据覆盖相同范围，不写“全面领先、完全替代、所有任务都能节省”。

### 行业争议评论的推理边界（2026-11-09 样本强化）

来源与文型记录见 [行业争议评论型](style-profiles.md#行业争议评论型--用一次发布回应公共疑问2026-11-09-单样本观察)。以下是由样本论证跳跃提炼的核验规则，不确认其模型、榜单、公司或训练事实。

- **成绩不证明训练来源。** 在反蒸馏措施之后发布、榜单提升或厂商声称架构原创，都不足以证明未使用蒸馏，也不能据此判定依赖蒸馏。若要反驳“全部靠某种方法”的全称主张，反例本身须独立证实；一个已证实反例也不能代表整个行业的训练来源。
- **区分单模型高点与行业梯队。** 写“差距缩小”时先指明是同口径单项分差、某个模型的能力，还是行业整体。讨论梯队需要在相同日期、指标和可用条件下，检查接近前沿的独立机构数量、任务覆盖与持续发布情况；不得把单家公司的高分外推为整个生态已追平或落后。
- **连续版本不等于持续突破机制。** 版本号与发布次数只能证明有迭代记录；可比较的多轮进步、独立复现及跨任务表现才能支持更强判断，仍不足以直接证明研发长期可持续或商业成功。名人称赞与社区声量不能补足这些证据。
- **“第一”要先说明排名函数。** 若作者把能力、速度、价格/额度、地区和账户可达性、稳定性、信任及表达可读性合成一个总称，应先列出这些轴及目标用户的权重；它们不能互相替代。没有同一任务集、版本、推理档位、Harness、预算与验收协议时，只能归因为作者的市场判断，不能包装成同题横测或全体用户的冠军。留言中的相反体验用于找任务域和使用条件，不按点赞或个案投票决定赢家。DeepSeek 1017 排名评论的来源和反例仅见 content-ops `data/model-corpus.md`“AI野史⑧”条目。
- **名称、服务与权重分开核验。** Pro/Flash 等命名不能保证能力或成本定位，须回到具体版本、任务、时延和费用。API 已可用、计划开放权重、权重实际发布、许可证允许哪些用途，是不同状态；预告开放不能计为已经开放，开放权重也不自动等于完整开源。
- **技术差距不直接决定估值差距。** 两者没有可直接换算的比例。讨论估值应另查估值日期与交易口径、收入及其确认方式、客户、成本和市场条件；作者回复中列出的经营解释只算待核验假说，不能当作这些公司已具备相应条件的证据。
- **留言用于发现问题，不用于认证答案。** 赞数、作者回复、读者印象与回复中转述的 AI 答案均不能替代一手材料；“跑分高为何声量小”等提问可以形成研究线索，不能预先认定产品、社区或信任就是原因。评论引发的反例应回到正文检查适用范围，而非以作者认可终止核验。

## 文章决策

每篇只回答一个尖锐的“为什么现在值得在这个平台调用”。不要做通用功能清单，也不要重复近期文章已经用过的同一论点。

### “单价—用量—任务成本”三层账本（2026-09-23 Grok 4.7 调研炼入）

推理模型写价格时，强制分开三层：

1. **单价**：输入、缓存输入、输出、工具、区域、加速服务和长上下文阶梯价；
2. **用量**：每项任务的输入、推理、可见输出、缓存命中、重试、工具调用和上下文重传；
3. **任务成本**：在同一任务与同一验收标准下，模型最终产生的 API 费用、订阅额度、运行时间和人工复核。

“同价升级”只说明第一层没有变化，不能直接推出第三层不变。出现“单价便宜但输出更多”“Fast 价格与速度同时翻倍”“跨过上下文阈值后整条请求升档”时，应把价格写成条件分支，并用可复现公式或第三方同题测量解释。订阅计划的额度下降、API 美元账单和评测方估算是三种口径，禁止混写。

**大众读者费用解释补充（2026-11-09 科技狐样本）**：若公布单价后仍有“贵不贵／写代码省多少”的疑问，先给明确假设的输入、输出、缓存命中量与时段，再按同单位计算 `(命中输入量×命中价 + 未命中输入量×未命中价 + 输出量×输出价) ÷ 计价单位量`；如跨时段／阶梯则分段求和，工具等费用另列。示例必须标“假设算例”，不冒充真实任务账单；比较旧版须补旧价、同任务用量和验收结果，不能只答“不贵”，也不把百万 token 换算成没有分词依据的固定字数。来源与报价仅见 content-ops `data/model-corpus.md` DeepSeek“科技狐发布速览吸收”及其回指账本。

### 推理档位经济性与切换阈值（2026-09-23 Grok 4.7 调研炼入）

模型支持 low/medium/high/xhigh 等档位时，先做“档位—质量—用量—速度—任务成本”矩阵。若相邻档位在综合分数上相同但用量、速度或成本差异明显，默认建议从较低档开始；只有更高档能改变困难样本的完成层级、减少重试或降低人工接管时，才有升级理由。综合指数相同不等于最难子任务完全相同，结论必须保留任务边界。

切换建议不用“新模型更强所以全部迁移”，改用**失败触发式迁移**：先找上一代会停滞、漏验收、反复重试或需要人工接管的真实任务，固定输入、工具、权限和完成标准，比较是否做完、能否恢复、总用量、总时间与人工补救。新模型多花的钱若省掉一次重跑或把原本做不完的任务做完，才可称为任务层面的便宜。

面向开发者的结尾优先给“任务—推荐档位—升级条件—观察指标”，而不是只给模型总排名。面向消费者时另列入口矩阵，区分网页、移动端、插件、IDE、API、模型网关和分批开放；二手报道中的“已上线”不得覆盖官方模型卡或用户账户的实际可用状态。

### 同一官方体系内的口径冲突

发布页、模型卡、文档、Release Notes 与实时模型页可能同时出现不同分数、知识截止时间、阈值或入口状态。发现冲突时记录页面、访问时间、版本和精确差异；优先使用最接近原始评测且带版本日期的材料，或在正文并列说明。不得擅自取平均、挑最大值，或替官方猜测哪一页“才是真的”。若冲突不影响核心判断，删掉该数字并把它留在证据卡与发布前复核清单中。

### 发布页可切换图表与比较标题（2026-09-23 Grok 4.7 官方发布页入炉）

当官方页面允许在成本、Token、步数、速度或成功率之间切换图表时，逐个记录图表指标、任务范围和页面当前选项。不要只看默认选中的视图，就把综合优势概括成“性价比最高”；同一模型可能在分数、费用、输出量和耗时上各有不同位置。正文应明确“按哪一项指标、在哪一套任务、对比哪些模型”得出判断，并尽量把完成质量与完成代价并排呈现。

标题或副标题使用“快一倍、便宜一半、同价更强”等比较句时，要在同一句或紧邻段落交代比较对象和口径。厂商若同时使用“相对竞品更快/更便宜”与“相对上一代同价/同速”两种参照，必须分别说明，不能让读者误以为它们指向同一个比较对象。

官方总表可按任务域并列编排，让读者看见能力分布；每行同时保留基准名称、版本、模型模式/推理档位、评测或 Harness 归属与星号脚注。对于明显改变排名的口径差异，正文就近说明，不把注释挤到文末，也不把合作方或厂商报告的数据写成作者亲测。

单样本可复用的组织方式是：先用最能改变选型的能力指标抓住注意力，再补成本机制（区分标价、缓存和完整任务成本），随后用长任务或合作伙伴案例说明生产含义，最后交代安全/审核边界与适合人群。该顺序是条件性模板，不要求每次完整复刻；证据不足时删减模块，不用宣传语补齐。

若上新伴随 API 安全策略或上下文处理变化，增加一条“机制—影响—兼容”支线：先给出开发者可观察到的请求/响应变化，再解释厂商要防的滥用方式，随后列出严格模式、兼容模式和不受影响的账户/产品范围，最后说明对 Agent、长上下文、自动压缩和缓存复用的迁移建议。不要把安全动机写成已被证实的唯一攻击来源，也不要把兼容方案省略成“会报错”。

发布日资料很多时，可采用“即时利益钩子 → 官方证据声明 → 总览跑分 → 少数精度/成本曲线 → 真实案例或科研应用 → System Card 安全矩阵 → 准入、可用范围与下一步”的顺序。必须把“作者亲测”（如额度到账、界面状态）与“官方展示/官方估算”分开标注；同一模型在不同思考预算、产品入口或 safeguard 设置下的成绩不能混成一个单一排名。

行业媒体改写时，可把“标题的强主张”降级为待核验引语，在正文首段交代发布时点、模型定位和开放范围；每个数字段落至少保留一次来源归因（官方公告、技术报告、模型卡或合作方），末段必须补“尚未充分验证的任务维度”和适用边界。这样既保留快讯的信息密度，也不把新闻稿写成无条件背书。

当发布页面或评测数据在预热稿、快照和正式公告之间发生变化时，新增“版本漂移核验”：记录每次变更的时间、页面版本、指标、比较对象、系统/工具配置和官方说明。正文先陈述可复现的页面差异，再讨论可能原因；“作弊”“注水”“手动削弱竞品”等只能作为待核验指控，除非有独立证据证明主观故意。若官方提示词指南披露了模型的追问、停滞、冲突或文风问题，可作为产品限制和迁移建议的证据，但要标注为官方建议，不等同于作者亲测。

官方发布科普稿可采用“复杂目标能否交付”主问题：把基准、上下文、异步工具和电脑操作翻译为步骤、等待、失败修正和人工复核等工作后果；价格段区分 Token 标价与单项任务总成本；客户案例标为官方/客户自述；AGI、零日漏洞等表述必须保留归因、开放范围和安全限制。

当文章继续讨论产业链影响时，先建立“能力→工作负载→系统瓶颈→基础设施环节”的推演链。训练与推理分开写，明确 Agent 多轮调用、KV-Cache、工具沙盒、CPU、互联、存储、散热和电力各自的传导关系。对需求增量使用条件句，区分技术推演、厂商披露和市场事实；禁止从模型发布直接推出股价或个股建议。

面向专业工程场景时，新增“演示—交付边界”检查：压缩回放、单项 Benchmark 或官方案例只证明局部能力；正文必须列出从输入、操作、自动检查到人工复核和实物/线上验证的缺口。优先用局部、可核对任务做迁移建议，并用漏项、返工、复核时间和验证覆盖率评价，而不是给出未经实测的提效倍数。硬件工程不得把 PCB 文件生成写成制造、上电或带载测试通过；嵌入式代码生成不得写成设备运行稳定。

首批实测稿可将“作者亲测”扩展为“可复现任务证据”：固定同一 Prompt 和输入，记录模型版本、工具链、耗时、交互状态及失败点；对 SVG、动画、3D、游戏和外部软件操作，优先提供可查看的成品、录屏或交互结果。模型能调用工具不等于所有工具任务都稳定，正文需标明当前测到的范围与未覆盖的边界。

面向大众解释复杂模型发布时，可采用“类比先行、机制落地”的写法：先用一个易懂比喻解释同底层模型与不同安全策略，再明确类比的技术对应物；随后用最多三个跨行业案例承接能力，不再堆叠所有榜单。每个案例至少交代任务难点、模型动作和结果证据，案例之间分别覆盖工程、科学和生物等不同工作类型。

若资料同时包含官方跑分与第三方实测，应强制加入“反向核验段”：检查输出 Token、Effort/思考预算、默认回退模型、缓存命中、拒答计分和产品入口，说明为什么 API 单价下降不必然等于单任务成本下降。综合指数可以帮助读者定位梯队，但不能替代针对代码、科研、中文或部署场景的专项判断。

模型测评必须做“三角比较”：上一代同型号、同厂更高/相邻型号、主要竞品。若新模型只在前两者之一上显著领先，应明确写出另一条基线；对已集中在高分区间的基准，说明边际提升可能不易转化为日常体感。把“从 42% 到 55.8%”等代际涨幅拆成百分点变化与相对增幅，禁止用单一百分比制造跨基线错觉。

当测评对象能控制真实设备或带反馈的外部软件时，三角比较之外增加“同题同场协议”：固定设备、输入、入口、权限、Prompt、人工看护和验收方法；允许模型自行决定动作路径、速度和验证方式，以观察其默认意图补全与风险偏好。结论按覆盖、风险、验证、交付和成本五维展开，不用“都完成了”掩盖完成标准差异。

当模型上新文章延伸到 C 端/B 端商业化时，增加“用户价值—变现价值—战略期权”三层账本：区分使用量/留存、个人付费、企业预算、服务成本、替代品压力和未来入口价值。不要用 MAU、下载量、榜单热度或单个用户故事直接推出商业成功；对订阅、广告、硬件和 API/办公等路径分别记录买单方、收入口径、成本、合规与迁移风险。

对专业模型或工具上新，增加“功能—资产—管线”三层核验：功能演示证明模型做了什么，资产检查确认结果是否可编辑/可导出，管线测试确认能否进入真实生产。3D 生成尤其要拆分几何、拓扑、材质、贴图、动态、格式、批量和 SDK/MCP 集成；速度、最低价格和路线图必须标注官方口径、版本和未验证边界。

专业测评标题可以用“胜负手”“及格线”“从 Demo 到管线”等强判断，但正文应提供针对性压力样本和下游交付证据。没有第三方基准或品类覆盖不足时，保留条件性结论；公司的训练数据、客户场景和未来世界模型只能按已披露事实、作者推断和战略想象分层。

真实世界 Agent 的完成证据至少分为：动作发生、目标状态达到、反馈稳定、异常可处理、交付可复用。设备视频只能证明动作和观感，不能替代传感器、串口、日志或软件状态；模型输出的 success 文本也不能替代外部证据。对速度、边界、扭矩、急停、二次确认和人工看护单独记录，不能把安全提醒写成泛泛免责声明。

多模型对比允许使用角色隐喻和传播性强的判断句，但隐喻必须由动作序列、参数、日志、账单和失败/复盘证据承接。成本段区分模型标价、工具调用次数、上下文重传、缓存命中、Token、设备时间和人工复核；没有严格隔离时，明确写成一次实测观察，不外推为普遍单任务成本。

当文章需要给出切换建议时，采用“任务—模型—代价”三列判断：日常短编码、长时间 Agent、科研/高风险任务、成本敏感场景分别说明推荐模型、理由和限制。不得因为单项榜单领先就建议所有用户迁移。

发布前传闻稿应建立“信号账本”：记录线索来源（用户观察、路由/版本痕迹、EAP 代号、社区发言、官方回应）、可验证程度、支持的最小结论和不能推出的结论。模型名称、发布日期、功能上线和竞争意图分别标注为“观察/推测/待确认”，不能用多条弱线索叠加成确定事实。

可按证据选用以下模块，不强制全部出现：

1. **开场**：准确时间、上线了什么、最有后果的一项变化。
2. **能力证据**：可信基准，以及该指标具体衡量什么。
3. **经济证据**：区分 Token 单价和完成一个任务的成本。
4. **工作含义**：把结果翻译成具体开发、业务或创作流程。
5. **限制**：简洁说明什么场景仍应选更强或不同的模型。
6. **谁该切换**：给出适合和不适合的具体任务。
7. **调用入口**：可用状态、兼容接口、迁移成本、当前活动、文档或咨询路径。

删掉重复模块再增加小标题。标题默认给多个陈述句方案，把模型名放在靠前位置；比较和数字必须有明确对象并被正文兑现。小标题可以使用张力、数字、对比或具体后果，但不能制造正文无法支持的冲突。

- **身份上下文逐请求验收。** 不能只检查凭证已签发或写入浏览器；列表、详情、预览 URL、授权、删除等入口逐项核对身份是否传递、服务端是否校验。补全新无痕窗口、缺失凭证、错误凭证和跨用户凭证的负向测试；把自动门禁结果与真实隔离结果并列记录。
- **素材生命周期与快照分别验收。** 区分用户素材、任务快照与任务产物；逐项测试软撤销、替换、硬删除和级联删除，核对外键策略。使用稳定 ID/object key 作为持久引用，不能把签名 URL 当作永久引用；去重还要检查响应字段契约。源素材修改后重新核对冻结引用，不能由软撤销推断硬删除后仍完整。
- **mock 必须实现服务语义。** 对齐真实服务的过滤、查询参数、授权与状态变化；遇到有效断言失败，先检查模拟接口是否遵守契约，不能靠删除断言消除失败。免费 mock 验证与真实 Provider 调用分开记录，后者交代实际范围和费用证据。
- **知识必须改变可操作机制。** 先分析 PRD 和来源资料，再按知识类型选择组装、排序、图构建、Schema 编辑或预算分配等操作；理解差异应影响状态、失败、复习和通关。保留 path/hash/anchor 等来源追踪和可重建同步入口，并核验内容变化后索引是否一致。验收完整通关、失败复习、结算报告与刷新恢复，不能只检查首屏能运行；流畅试玩不等于学习效果得到验证。
- **保留前置劳动和比较条件。** 交代资料准备、PRD、确认环节、迭代和人工验收；不能把详细规格驱动的结果写成一句提示词的自主创造。同提示词只是比较条件之一，缺环境、评分、重复实验及完整耗时成本时，模型差异只保留为作者单次观察。可选叙事顺序为任务约束、实现证据、反例和复验建议，不升级为固定文章模板。

## 小版本发布：成本前沿、低提示演示与入口摩擦（2026-11-09 样本补充）

适用于以小版本更新解释能力、任务经济性和使用门槛变化的发布解读。来源、型号、数字和去重后的评论线索唯一记录在 content-ops 的 `data/model-corpus.md` DeepSeek 第13、16节；本节只维护方法，不复写报价、认定产品事实或进行账号风格终审。

- **成本/质量图先验坐标和分母。** 取原图核对横纵轴、币种/汇率、任务集、版本、推理档、工具预算、样本量和误差；区分每次尝试、每项任务与每成功任务的平均费用，记录失败、重试及工具是否计费。核对线性／对数刻度；对数轴上的视觉距离不等于线性差额。纵轴为 Pass@1 时，不将横轴每任务费用改写成每成功任务费用；不同 Harness 与报价生效时点逐一保留，统一条件前不能把混合曲线当作严格横测。缺少原图只能归因转述，不能计算精确倍率。所谓成本前沿只对图内、同条件的比较对象有效：只有不存在另一个成本不高且质量不低、至少一项更优的点，才可讨论其处于前沿；这不证明全市场或全部任务第一。
- **“同价更省”回到既有三层账本。** 继续使用本手册“单价—用量—任务成本”，不另建平行定价规则。峰谷价格另核时区、时段、生效日期和缓存未命中价；缓存率注明分母与输入/输出构成。输出变短或响应更快要同时检查完成度、漏项、重试和人工补救，不能只用字数缩短证明任务成本下降。
- **低提示演示保留完整交互账本。** 记录初始需求、参考素材、提示长度、追问/修改轮次、后台自动迭代、失败重跑、工具/框架和交付文件。少量用户对话不等于没有内部重试；模型、Harness 和外部工具共同完成的结果分层归因。训练方法需原始技术说明支持，不能从演示效果反推训练因果。
- **把愿望变成验收项。** 从读者想要的结果补出可执行规格：运行方式、输入操作、核心机制、状态恢复和交付格式。图像/视频只能证明可见部分，复杂场景、可玩游戏与原作复刻各需相应工程和交互证据；技术术语的通俗说法不豁免验收。
- **入口便利性包含摩擦。** 具体体验入口同时核验账户资格、模型 ID/版本、可用工具、免费或付费额度、速率、排队、超时和恢复条件。网页聊天、工具客户端、自行调用和第三方积分计划分别描述，模型价格低不能推出平台随时可用；短期赠金与积分按活动条款另查。
- **评论先去重，再形成问题。** 重复粘贴的留言按可见作者标识、文本和回复关系去重，缺失图片不臆测；页面留言总数与可见独立留言分开。排队、限额、不会接入与账单自述用于列补证问题，不据赞数推定普遍性、用户比例、转化效果或典型成本。
- **多轮检查任务范围是否保持（2026-11-09 科技狐样本补充）。** 对“前几轮遵守、后续擅自扩展”的个体反馈，固定用户目标、允许修改范围与验收条件，按轮保留需求变更和执行差异；区分完成目标所必需的依赖工作、明确授权的扩展与未请求功能，记录首次偏离、额外用量／工时和纠正后复发情况。同样保留完成顺利的反例，不以单条抱怨概括模型，也不把自主多步执行一概视为越界。来源只存 content-ops 语料库同名吸收节。
- **配置答疑先分云端使用与本地部署（同样本强化）。** 面向不会接入或安装失败的读者，先确定产品、客户端、操作系统和版本，给经核验的最小入口及操作；云端推理的终端要求与本地加载权重的硬件要求分别取证。“模型有视觉能力”另核该入口能否上传图片及格式／大小限制，作者回复或模型规格不能替代客户端验证。能力、入口和配置各回答对应问题，不用一句“配置不高／支持”覆盖全部。
- **小版本叙事只作为候选编排。** 可以先提出更新与既有预期的落差，再用证据回答能力、任务费用和入口问题；不预设小更新必有大突破，不从宕机、命名或后缀推导上新、性能和日期。“图片”占位不视为已看过图表，不把账号口癖、谐音梗和绝对排名写进长期规则。

**五例演示补充（2026-11-09）**：来源与案例唯一见 content-ops `data/model-corpus.md` DeepSeek“欧巴聊AI 五例实测吸收”，本处只增补以下适用条件。

- **熟题锚点先固定对照条件。** 连续版本使用同一保留节目时，保留相同输入／提示、初始资源、验收项及重复次数，记录模型修订、Harness、推理档、工具、环境、预算和人工介入的变化；环境有变化就披露并补对照。熟悉旧画面不等于有旧版受控结果，未补齐条件只写作者的版本观察，不把印象升级为提升幅度。
- **多例按互补机制组织。** 特效看阶段和连续性，SVG 看对象关系与循环，游戏看操作、判定和状态流，复刻看机制与内容差异，动画看渲染与成片交付。按任务目的选择维度，不套固定案例数或难度阶梯；选项多、首屏漂亮和视觉像真各不能代替机制完成、内容有效和物理验证。只在有物理依据与验证时作模拟准确性结论。
- **程序视听分别核产物和资源来源。** 区分代码渲染、录屏、成片导出和生成式视频调用；先取源文件、运行／导出步骤，再核对应能力。宣称无外部资源时，检查素材与依赖清单、资源路径、运行时网络及冷启动／离线加载情况，明确预缓存和工具范围；使用库与使用外部视听素材分别记录。证据只覆盖被检查的案例和阶段，不能从一例推广到整组，也不推断未披露的音轨、导出格式或模型原生能力。

## 证据型配图

图片用于证明段落中心主张。优先原始图表、官方产品界面或模型方素材；无法直接取得时才用截图。每个图片建议包含：图片或图表名称、原始来源链接、放在正文哪一句之后、一句中文图注、必要的裁切建议。

不得去除来源品牌，也不得裁掉坐标轴、指标名、日期、图例和脚注等解释图表所需信息。找不到能证明该段的图片时，宁可标记缺口，不用泛用装饰图冒充证据。

## 从可运行到继续维护，以及分阶段用量假说（2026-11-09 巧儿样本炼入）

适用于两份完整项目均达到基本可用、文章需要解释后续采用选择的横测。案例、数字和作者归属唯一保存在 content-ops 的 `data/model-corpus.md`「巧儿三任务横测」节，本节只维护方法；单样本不改变账号风格或模型分工规则。

- **把共同完成与采用理由分开**：先交代两边均通过了哪些基础要求，再用“运营者完成一次操作”“维护者修改一项业务”解释差异。菜单是否围绕任务、时间是否可读、状态控件是否贴合语义、图片能否上传预览，以及接口／服务／页面能否定位，均可成为待验证对象；不能只凭截图宣称代码易维护。不同任务可选不同模型，整体无须选唯一赢家。
- **联动演示沿状态链取证**：用“改变输入 → 内部状态 → 多处输出 → 异常触发 → 解除后恢复”核对交互，比按钮存在更能说明系统是否接通。展示不同保护或恢复行为时描述条件与结果；若没有专业标准和验证，不将演示逻辑评为真实设备安全方案。
- **将按阶段换模型写成实验**：探索与规划交给更强模型、边界清楚的修改交给低成本模型，只有取得同题记录后才能称省用量。交接至少带业务约束、接口／数据契约、允许修改范围和可执行验收项。对照全程同模型与分阶段协作时，统一完成标准并分别记录 Token、套餐额度、实际费用、耗时及人工介入；把交接解释、重试、返工和最终验收计入总投入，不用调用单价代替任务总成本。
- **标题必须兑现证据强度**：成品对照不自动证明省 Token，订阅消耗占比也不证明节省。若正文只有下一轮计划，标题与结尾都应明确是拟试方法；“最省”需要比较范围和实测基线。作者对氛围或省心程度的偏好保留归属，不替代测试记录。

## 推理服务栈横测：模型、引擎、草稿与硬件分层（2026-11-09）

适用于开源模型换代、注意力机制变化或推理引擎首发适配的性能文章。具体型号、数字和来源指纹唯一记录在 content-ops 的 `data/model-corpus.md` 对应条目；本节只维护可迁移方法，不复制单篇文章的数字账本。

- **先冻结比较条件。** 同时固定模型权重、引擎版本与 commit、CUDA/驱动、容器或 day-0 镜像、采样参数、量化、并行配置、GPU 型号与数量、输入/输出长度、请求分布和预热策略。若引擎、草稿模型或硬件变化，必须拆成新的实验臂，不能把差异归给主模型架构。
- **把草稿解码单独记账。** 记录草稿模型版本、每步最大 K 值、实际平均接受长度、拒绝比例、回退次数和主模型额外计算；草稿接受率低时，不能用主模型单独解释速度变化，也不能跨 K 值直接横比接受长度。
- **设计上下文与并发矩阵。** 至少覆盖短/长上下文和低/中/高并发，例如 C1、C8、C32；明确 C1/C8 是每用户 decode 还是单请求速度，C32 是总吞吐还是平均速度。固定输出长度只用于吞吐校准，不替代质量评测。
- **阶段指标不能混写。** 分别记录 TTFT、prefill、decode、排队等待、端到端完成时间、总吞吐、每用户速度、失败/超时/重试和有效输出 token。API 报价、单卡每小时产出与真实任务成本分列，不能以任一项代替另一项。
- **核验 GPU 执行路径。** 对 CUDA Graph、eager、专用 decode、persistent kernel 等路径记录是否启用、触发条件、CTA/SM 资源要求、实际回退原因和日志证据；机器资源差几个常驻 CTA 也可能改变整条路径，不能只看配置文件里的“已支持”。
- **解释稀疏注意力的收益边界。** 分开索引/筛选、压缩记忆读取、精确注意力和调度开销；比较单 token decode 与一次处理多个 token 的路径，并按上下文长度、并发和 batch 观察拐点。长上下文收益不自动外推到短上下文，理论访存减少也不等于端到端加速。
- **能耗分层报告。** 说明是 GPU/DCGM 积分、主机功耗还是整机墙插功耗，记录采样窗口、空载基线、GPU 数量和是否含 CPU/DRAM/风扇/电源损耗；输出每 token 能耗时同时给出吞吐和有效输出口径。
- **建立三层成本账本。** 第一层是模型输入/输出单价与缓存规则；第二层是机器时租、GPU 数量、利用率和每卡每小时产出；第三层是一次真实任务的上下文、重试、工具、排队、人工和失败成本。没有完整账单时只能报告单位价格或作者口径，不能宣称任务成本下降。
- **结论必须绑定服务栈。** 文章可判断“某模型 + 某引擎 + 某草稿 + 某硬件 + 某调度路径”的表现，但不能据此写成模型架构全面落后或普遍更快。缺失原始表、硬件、版本、日志或账单时，保留为作者报告并列出复测清单。


## 非对称架构发布：阶段、缓存层级与别名迁移（2026-11-09）

适用于把模型结构、缓存压缩、降价与 API 换代放在同篇的发布稿。来源主张与具体型号／数字唯一见 content-ops `data/model-corpus.md` DeepSeek 第 11 节；本节只存核验与组织方法，不作风格终审。

- **新增：阶段比大小。** 分开总参数、按输入／输出阶段的激活参数、计算量与实际时延；不把各阶段激活相加当模型规模，不从参数比例推算质量或成本。结构、训练和部署同时变化时，未经消融不单独归因。
