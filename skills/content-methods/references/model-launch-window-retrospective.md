# 模型上新全流程复盘：Grok 4.7（2026-09-23）

本文记录一次从参考学习、事实调研、成稿修订、找图到公众号排版和封面生成的完整协作经验。它保存的是用户明确表达的工作偏好与可复用纠错，不是 Grok 4.7 的事实资料库；后续写 Opus 5.5 等主题时，所有版本、数据、价格、排名和来源都必须重新核验。

## 协作顺序：先学，再判断何时动笔

- 用户说“先学别人的再写”或持续提供参考链接/文章时，先逐篇读取、归纳各自的切口、证据和判断；不要因为主题已经明确就抢先写稿。用户曾明确纠正过“还没让你立刻写”，说明过早产稿会错过真正想学的材料。
- 用户说“读现在页面/继续读”时，读取浏览器实际打开的页面内容；若页面有选中文本，先读选区。不能只凭 URL、搜索摘要或上一次页面内容假装读过当前页面。
- 阅读阶段应简短汇报新增认识，并在用户问“够不够写、还缺什么”时指出精确缺口，例如原始成本口径、争议分数的版本、社区实测设置、厂商路线图的原始发言。不要拿泛泛的“还需更多资料”作答。
- 用户明确让“去找并写几千字”后，按“补证 → 证据卡 → 文章判断 → 成稿”的顺序执行；不要再反复确认已经给清楚的要求。若用户说稍后再写新主题，只记录待续意图，不提前启动调研或创作。
- 用户后续指出前稿“假大空”时，把它视为有效质量反馈：重看证据和段落功能，减少抽象判断、行业宣言与营销套话；不能只把句子润得更顺而保留论证空心。

## 调研与事实边界

- 多篇同题稿是学习材料，不是可直接拼接的事实库。官方发布/文档核实产品主张和接入状态；独立评测核实基准、条件与方法；原帖或社区讨论只证明对应发言/个案。保留来源并重新组织，不复刻标题、段落和原句。
- 把正文数字按“页面与日期—模型版本/推理档—工具或 Harness—指标定义—比较对象”逐项核实。发布页改版或快照不同造成分数冲突时，记录各自出处和版本，不擅自平均或择高引用。
- 成本论证分开核对 Token 单价、任务 Token 用量、推理/回答 Token 构成、实际任务成本和耗时；不能从低单价直接推出低总账单。社区的网页、3D、SVG 等演示需找到原帖及可见任务条件；单次结果不得泛化成模型整体能力。
- 参数规模、训练数据、延期原因及未来路线图，回到当事人原始发言或官方材料，准确归因。未见官方技术材料确认的内容不可改写成已证实事实；竞品文章、搜索摘要或生成式模型润色稿都不能替代源核验。
- 任何“已核实、已完成全篇核对、作者实测”的说法，只能在确实执行并有证据时使用。完成校对不等于证明所有事实正确。

## 成稿与二次润色

- 文章先确定一个会改变读者选择的问题，再用基准、费用机制、社区实测或路线图中的少数证据推进；不要把竞品文章逐条摘要成资料汇编。篇幅按用户要求，本次是数千字的完整稿，不将其升级为所有主题的固定字数。
- 用户明确选用 avoid-ai-writing、lieflat-less-ai-tone 等写作技能时，按其规则清理，不改变未授权的文章事实和结构。可迁移的具体反馈包括：减少机械的“不是……而是……”翻案句、虚构读者视角的空转转场、密集顿号长串；将列表整理成实际工作流程；让段落由事实、因果、比较和条件推进。
- 生成式润色版本可以作为表达反馈，不自动成为事实来源或终稿。保留逐条归因，来源贴近对应主张；对测试样本、档位和不确定性作必要限定，避免“已全面领先/落地翻车”等超出证据的概括。

## 配图：证据图与封面图分工

- 用户要求“找图、不要生成”时，用原始官方图表、产品页面、作者原帖或可信评测图；按约每 300 字检查是否需要一张图，但这只是密度参考，图片必须支持附近论点，不能为凑数添加装饰图。交付图片来源、插入位置、图注和裁切建议。
- 用户提供截图时先盘点并尽量逐张对应文章内容；保留图表轴、图例、脚注、署名和可核验的来源 UI。不得为凑统一版式拉伸或裁掉证据信息；图片涉及转载时提醒确认授权。
- 用户单独明确要生成封面时才调用图像生成。封面要体现具体模型/产品身份；泛化的发光大脑、机器人或代码流不能代替 Grok、Opus 等可识别名称或经核实的品牌线索。不要伪造官方 Logo。
- 一图兼容 2.35:1 与 1:1 时，用宽幅画布并将产品名、标识和主体压入中央方形安全区，侧翼只延展低细节背景；生成后实际检查中央方形裁切。标题若贴近裁切边界，应缩小重排，而非只凭宽图效果验收。

## 公众号排版与交付

- 用户提供参考版式时学习信息层级与组件节奏，不照抄参考品牌、图标或配色。此次用户指定的起点是：正文 16px，H1 20px 加粗，H2 18px 加粗，行高 1.75—2 倍、字距 1—1.5px、左右约 12px 留白、段落有明显间隔；采用一主色加两辅助色，按当篇主题另选配色。这些是用户偏好的版式参数，不覆盖其后续明确指定的账号规范。
- 微信实测出现行高小于字号时多行文字重叠，以及文字对齐异常。多行正文显式设置内联 `line-height`；16px 正文用 28—32px，避免依赖编辑器默认值或只调外层容器。粘贴前用公众号合规检查器验证 `<span leaf="">` 包裹，并实际在编辑器预览检查对齐与行距。
- HTML 预览和微信成稿要区分：本地相对路径图片只适用于本地预览。交付文章 HTML 时把素材放在配套文件夹并附带复制预览；正式发布前逐图上传公众号素材库，将本地路径换成平台图片地址。
- 用户撤回旧方案（如放弃另一个排版 Skill/主题）后，以最新明确要求为准，只修改仍在范围内的现有文件，不继续做已取消的方向。对已有成品采用新文件或版本化文件，保留原稿，汇报改了什么、没动什么。

## 后续复用边界

未来用户启动 Opus 5.5 等模型主题时，可复用上面的协作顺序、证据核验、文章修订、配图和排版规则；不能沿用 Grok 4.7 的数据、结论、来源或封面元素。优先根据用户当次提供的参考和纠正更新判断，避免把这次的一次性视觉选择扩张成所有账号的固定品牌模板。
