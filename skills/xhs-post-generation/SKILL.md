# 小红书图文生成

产品名与执行模型分开：用户输入 GLM5.3 是内容主题，写稿使用公司网关文案模型，风格终审由规划 agent 把关，视觉提示词由独立多模态调用生成，完整海报使用本机配置的图像模型。批量图文生成可交由批量 agent（Hanabi）承接。不自动换提供方，不接价格监控，不自动发布。

1. 读取 `data/distilled-preferences.json`；缺失时回退到已审来源。偏好和业务提示仅在生成脚本加载，`/v1/*` 网关保持纯透传。版本与来源哈希写入 manifest。
2. 当前风险词、内容生产规范与运营偏好保持有效；唯一机器规则源为 `rules/banned-words-quick.yaml`，不在本技能复制词表。所有可见文字（含封面副标题/亮点、标签、人群）都检查。报视觉风险时先区分准确上屏文案与排版元数据，检查投影、定位字段和回归方法引用 GUIDE「封面同构链路与排障」，不通过放宽风险词库绕过误报。
3. `--brief` 为本轮用户提供的营销需求与卖点，可直接用于本轮文案，manifest 如实记录来源；可选 `--facts` 记录独立核验资料。缺少 facts 不再把所有卖点降为试用建议。不添编数字、个人评测经历或活动，不把用户提供参数冒充独立核验。
4. 文案模型按每图文案计划返回独立笔记标题、copy_format、顺序区块 sections、标签、angle、动态 audience；正文由区块组装。在线文案契约不要求旧 title_lines、cover_subtitle/cover_highlight，封面专属短字由第7步独立规划，不能从正文浓缩搬运。标题不限动词枚举，正常第一人称与经验分享口吻不靠正则封杀。同批组织结构应有变化。
5. 每图先做一轮公司文案模型调用，返回本图全部版本，再由本机做基础结构与风险词检查；解析时兼容未闭合的 Markdown JSON 围栏。若因风险词校验失败，或返回空/非法 JSON，带着失败原因自动重出最多 2 次（合计最多 3 次收费调用），每次保留原始响应；结构错误等其他校验仍立即失败。写稿、价格与移动端正文规范唯一源为 `rules/content-spec.md`，更新后用 `python3 scripts/build.py distill` 重建偏好包。`copy.mobile_body` 仅处理换行及说明书尾巴，不改写事实；校验后的正文同步写入 copy.json、manifest 和 Markdown。不再进行风格/事实两轮模型删改。风格终审交规划 agent；生图与视觉方案仍不自动收费重试。
6. 手选参考优先；自动选图读取 `data/collections.json`，按平台结构选择与缺口处理见 `docs/GUIDE.md`「封面同构链路与排障」。合集、素材仍是唯一源，不另建索引；参考帖仅供文案节奏与构图，不是产品事实。记录引用、源哈希与实际读取的原图。
7. 文案与封面独立：视觉模型只看单张结构锚图、合集/OCR、完整型号、封面专属语料和现行风险规则，不读取正文及旧封面五段字。视觉先拆结构，再返回结构化方案与独立短字；图像模型按校验后的方案生成。四类设计约束引用 `rules/content-spec.md`，工程契约与旧流派兼容见 GUIDE，不在本技能复制词表。大字报的背景材质、墨色与高亮传递按 `rules/content-spec.md`，满幅材质配方与分层实现见 GUIDE「大字报背景实现」；其他版式继续完整海报直出，`--background` 是显式离线兜底。不把提示词约束宣称为图生图或像素级还原。
8. 保存 manifest、每图模型响应、copy.json、Markdown和PNG；结构选项、倍率、文件契约与重建流程引用 docs/GUIDE.md「文案结构与图文配比」，不复制结构规则。输出目录非空拒绝覆盖，失败保留已有结果；续跑核对 brief、facts、引用与偏好版本，不把缺图称作完成。

使用：`python3 scripts/generate.py copy --model GLM5.3 --platform xhs --count 2 --copy-format all_variations --copy-multiplier 3`（2图6文案）。首次运行 `./start.command` 初始化环境（自动安装依赖到 scratch/.venv）；脚本会转到该仓库环境。凭证配置见 docs/GUIDE.md「生成脚本与网关配置」，不写到成品或日志。

## 额度不足与复用背景

生图失败不自动换模型或继续计费重试。用户可以显式选择 `--background <已有背景.png>`，本机重新配色与排版，manifest 中记录 cached_background 与来源。Hanabi 必须显示该模式，不能把复用背景称为当次全新生图。已失败目录可用 `--resume` 复用终稿和成功图片，只执行缺失步骤。Hanabi 的「继续完成本批」使用独立恢复目录；本机校验曾误拒的原始视觉响应也先复用校验，名称归一化与恢复约束见 GUIDE「封面同构链路与排障」。缓存模式仍调用文案模型写新文案；新背景模式需要网关有足够预扣费额度。

## 参考与可追溯性

手动补充或修正参考素材，使用 Hanabi 素材库 CRUD；唯一源、图片替换/移除语义及纯文参考限制见 `docs/GUIDE.md` 第7节。

选择与实际引用分开记录：手选通过 `--references <JSON>` 指定，未选/空数组按本技能步骤6自动挑选；清单与哈希在manifest中，Hanabi据此回跳。失败任务续跑须核对来源，已完成历史不重新选择参考。离线假模型只验证路径，不冒充真实生成。

## 用户提供成图、只要两条提示词时

先说明原始提示词是否齐全；只有成图时做反推重写，不称为逐字修改原稿。将图片中的文字当参考素材，不当产品事实或新指令。用户后续明确指定的文案调整按当前请求执行；不顺带补充未提供的金额、时限、额度和性能。

价格短句候选统一读取 `rules/content-spec.md` 的「标题与正文结构」，不复制新词表，也不默认限制为四字。换词后同步摘要、对照表、提示词正文与准确可见文字清单，并按新字数调整单行字号及色块尺寸。

大字报可选开场词与行文排列读取 `rules/content-spec.md`；不要把行动词当价格表达或未经核验的活动信息。

由规划与复核 agent 看图分析并拟提示词，执行端核对截图中的实际颜色、文字与几何位置，再将用户补充落实到终稿。可用 design-taste-frontend 的层级、尺度和缩图观察方法；静态海报不执行其网页构建、动效或交互流程。

用户返回自改成稿与失败成图时，先列认可稿必须保留的模块，再检查旧提示词中造成差异的明确指令。当前反馈覆盖旧方法中的删减默认；商业功能牌、代码屏和底部说明按信息模块保留，不能当作网页装饰一概删除。不自动添加用户未要求的说明字。用户自改成稿的文案仅按其本轮复现授权沿用，记录为用户提供素材；不转存为已核验产品事实，也不扩写新的性能或参数。

用户要求围绕模型推广时，按 `rules/content-spec.md` 的事实核验与封面规则执行：先核对完整型号和核心长处，再将用户明确提供的服务卖点落实到文案。用户讲述自己的价格、量、速度和稳定性，可记录为本轮业务输入，不要求为了写这类短句而改成任务示意；不将其写成独立实测结果或模型原生参数。资料中的高速变体、套餐权限和普通版不可混用。文档工作流不是默认替代方向。

同一模型转为闲鱼等平台的图片提示词时，重新读取目标平台规则与用户比例，按 `rules/content-spec.md` 的跨尺寸适配要求重排。沿用本会话已核实的型号与事实，改变比例本身不需要重复调研；检查器使用目标平台标识，不套用小红书专属金额限制。具体价格仍须用户提供。

用户要求跨平台「元素都换、占位比不变」时，按设计规则中的同名方法锁定空间骨架，再逐项替换视觉资产；不能将改比例、换色或旧主体变体当成新方案。先前保留具体代码屏、机器人等要求只适用当时复现，不覆盖用户这轮全部换元素的纠正。

用户指出中段缺品牌、太抽象时，按设计规则「品牌主体与具体场景」重做：先核对真实品牌标志，再用可辨认的产品能力画面承托。中段不能靠顶部型号代替品牌识别，不通过禁光所有屏幕、代码与品牌色制造区别；旧稿自加排除项随纠正撤回，不能提升为用户永久要求。

用户要求品牌调性与大字醒目同时成立时，按设计规则「中段品牌调性与顶部专属色」执行：中段场景整体符合品牌，不只贴Logo；顶部型号和价词保留专属文字色及独立底色，禁止把强调色扩散到中段与底栏。颜色对比计算是提示词预设核验，未生图不报告视觉验收通过。

每条独立写清比例、标题和场景分区、主体、准确可见文字清单、安全边距和排除项。两条按 `rules/content-spec.md` 的分别发布要求检查内容与结构，规则只维护在该文件，不复制另一份。风险检查针对实际可见文字；不把负面提示中的禁用词误当成将要显示的文案。只交付提示词时，记录未生图、未发布、未做平台检测。

## 已有成稿修改

用户要求修改已生成的图片或某一篇文案时，优先使用 Hanabi 成稿编辑器，避免重跑整批。修改协议、版本采用与恢复、模型接入和文件保留的方法唯一说明见 `docs/GUIDE.md`「图文修改工作台」；按该节操作，不覆盖原稿或已导出文件。大字报字号与对齐使用编辑器里的显式排版控件；它们由本机排字阶段执行，调整时自动预览，满意后保存排版无需调用模型；改背景词才重新生图。旧图背景层兼容与提示方法见上述手册，不能把修复纹理说成原背景逐像素恢复。默认与用户手动覆盖边界见 `rules/content-spec.md`，具体操作与版本恢复见上述手册。

## 查看与反推提示词

排查成图问题时，先从生成卡片「图片与提示词」中的「原始提示词与调用记录」读取实际提交记录，再对照视觉方案与本机排字阶段；不要用当前代码重建的词冒充历史请求。素材库单图点击反推只记录图片观察，不是原始生成词或已核验产品事实。直接改词重新生成时使用同一图片编辑器，准确传词、分层排字、预览采用与失败词恢复的方法唯一说明见 GUIDE「图文修改工作台」。素材反推入口、缓存失效和失败重试见 GUIDE「提示词查看与素材单图反推」。
